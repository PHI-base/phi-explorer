# Session Log: phi-explorer Query CLI

## Overview

Picked up the single remaining item from `docs/BACKLOG.md`'s "Query CLI" section. Went
brainstorming (architectural path — no existing CLI flow to modify) -> design spec -> implementation
plan -> subagent-driven-development, landing a 5-subcommand `phiexplorer/cli.py` wrapping every
existing library entry point, plus solving the organism-lookup ergonomics gap the backlog flagged.

## What got built

### 1. Design spec

[docs/superpowers/specs/2026-08-20-phi-explorer-cli-design.md](../superpowers/specs/2026-08-20-phi-explorer-cli-design.md).
Key decisions from brainstorming: mirror the library 1:1 (no new extraction/report logic in the
CLI itself), `argparse`/stdlib only (no new dependency), fuzzy organism resolution (supply
either `--taxid` or `--sciname`, the CLI resolves the other and validates against the loaded
export), case-insensitive **exact match only** for sciname (no substring matching), file output
matching the existing `reports/generate.py` writers' defaults.

### 2. Implementation plan and execution (4 tasks, subagent-driven)

Plan: [docs/superpowers/plans/2026-08-20-phi-explorer-cli.md](../superpowers/plans/2026-08-20-phi-explorer-cli.md).
Worked directly on `main` (no worktree — explicit choice, matching how the three prior plans in
this repo were executed).

- **Task 1** — `chain.all_organisms()` / `chain.resolve_organism()` in
  `phiexplorer/dereference/chain.py`: dataset-wide organism lookup/validation, reusable outside
  the CLI. Clean review.
- **Task 2** — `phiexplorer/cli.py` skeleton: argparse setup, top-level `--input`, the
  `(ValueError, OSError)` -> `error: ...` / exit 1 boundary, plus `organisms` and `summary`
  subcommands. Clean review.
- **Task 3** — `phenotypes`, `effectors`, `organism-summary` subcommands, each resolving its
  organism via Task 1's `resolve_organism` before calling the existing `reports/` functions.
  Clean review — reviewer specifically verified the error-path tests exercise
  `resolve_organism`'s `ValueError`s through the full `main()` path, not in isolation.
- **Task 4** — `docs/FAQ.md`, `docs/BACKLOG.md`, `README.md` updated to describe the CLI, stale
  "not yet built" language removed. Clean review.

**Final whole-branch review** (opus) found the real value of a whole-branch pass: all four tasks
individually reviewed clean, but the assembled branch had 4 Important documentation/UX gaps no
single task's diff could show — `--help`'s `prog=` named a `phiexplorer` executable that doesn't
exist (`python3 -m phiexplorer.cli` is the real invocation), and three docs
(`docs/PORTING-NOTES.md`, `README.md`, `docs/FAQ.md`) still described the CLI as unbuilt or
unhelpful even after Task 4, because Task 4's own stale-language grep only covered the three
files it edited, not every doc that mentioned the CLI. One fix wave (single dispatch, all 4
findings), one scoped re-review, all addressed, no new breakage. The same review also confirmed
a genuine cross-task correctness point: `resolve_organism` returns the export's *canonical*
`full_name`, not the user's raw input string, so a case-insensitive `--sciname` match correctly
flows through to `extract_protein_phenotypes`/`extract_effector_proteins`'s exact-string
comparisons downstream — the Task 1 / Task 3 seam holds.

Four Minor findings were parked with rulings rather than fixed (see the deleted plan
workspace's ledger, summarized in this session's commits): missing `help=` text on subcommand
flags (plan-mandated shape), an unreachable defensive `raise` in `run()` (reviewer-endorsed as
fine), 3x-repeated `--output-dir` (reviewer explicitly recommended against a helper for 3
lines), and `all_organisms` widening the blast radius of an already-parked cosmetic
bracket-access finding in `chain.py` (still hypothetical for real PHI-base data).

Pushed to `origin/main`: `611f720..b642200`.

### 3. Obsidian CLI correction and write-workflow change

- User asked why phi-explorer wasn't using "the Obsidian CLI from author kepano" like
  OBS-BotVault does. Investigation found there is no separate third-party CLI in play:
  `~/.local/bin/obsidian-linux-cli` and the `obsidian` wrapper (which forwards to
  `/mnt/d/ObsidianProgram/Obsidian.com`) are the *same* official Obsidian CLI feature, just
  built for different platforms — confirmed via `obsidian-linux-cli`'s own config
  (`~/.config/obsidian/obsidian.json`, `"cli":true`) and socket file, and by cross-checking that
  `OBS-BotVault/Claude-Automation/obs-put.ps1` calls the identical Windows binary. Corrected the
  overstated "two completely different tools" framing in Claude memory
  (`reference_obsidian_runs_on_windows.md`).
- Given that, switched phi-explorer's vault-doc write workflow from disk-write-then-`reload` to
  BotVault's write-through pattern: `bash /mnt/z/OBS-BotVault/Claude-Automation/obs-put.sh <file>
  <vault-relative-path> phi-explorer`, which pushes through the CLI's `eval` route (Developer
  Mode is already on for this vault) and diff-verifies the result, catching a known truncation
  bug BotVault found in the CLI's `create` command. Saved as feedback memory
  (`feedback_obsidian_write_through_cli.md`), replacing an earlier reload-based memory from
  earlier in this same session.
- **Known gap this session:** Obsidian itself went unresponsive on the Windows side partway
  through (even bare `obsidian vault` health checks timed out) and never recovered before the
  session ended. The spec, plan, and Task 4's three doc files are all correct and committed in
  git/pushed to GitHub, but are **not yet visible via Obsidian's live index** — a manual
  `obsidian reload` or a re-run of `obs-put.sh` once Obsidian responds again will pick them up.
  No data was lost; this is a visibility-only gap.

## Decisions worth remembering

- **A CLI counts as architectural, not bounded, even though it's "just a wrapper."** No existing
  CLI flow existed to modify — per this repo's own established classification rule (see the
  2026-08-19 session log's bounded-vs-architectural note), new functionality with nothing to
  refactor is architectural regardless of how thin the new code is.
- **The final whole-branch review earned its cost again** — the fourth time in this repo's
  history that a final review caught something no task-scoped review could see (after the
  core-toolkit plan's overcount bug, and two stale-doc catches in the two follow-up plans). This
  time it was specifically a *documentation coverage* gap: a task's own verification step (a
  grep) was scoped too narrowly to catch every place its own subject matter was mentioned.
- **Worked directly on `main` again, by explicit choice** (declined a worktree when asked) —
  consistent with how all three prior plans in this repo were executed, not a one-off.
